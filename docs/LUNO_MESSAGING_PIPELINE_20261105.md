# 메시징 구현 및 데이터 파이프라인 검증

2026-11-05 KST. 사용자 지시: 개발 계속, 실제 메신저 서비스 구현, 디자인 개선, 커밋·푸시 보류. 이 보고서는 전체 파이프라인 무결성 보증이나 운영 출시 승인을 의미하지 않는다.

## 실제 구현 변경

- 웹 소켓 종료·티켓 실패 시 지수 간격(최대 30초)으로 재접속한다. 세션 변경·로그아웃 후 이전 콜백은 무시한다.
- 재접속 시 기존 sync API로 누락된 메시지를 순서대로 복원한다. Go의 messages/after_sequence와 현행 Worker의 delta_messages/since_sequence 응답을 수용한다. 마지막 50개만 가져와 중간 메시지가 빠지는 문제를 방지한다.
- 화면이 보이는 동안 10초마다 저장 기록을 대조한다. 기존 Cloudflare 구성에서 서로 다른 isolate 사이에 즉시 fan-out이 되지 않는 경우의 복구 경로다. 푸시 전달이나 실시간 SLA를 대체한다는 의미는 아니다.
- 네트워크 실패와 HTTP 거절을 구분한다. 서버가 거절한 전송은 자동 대기열에 넣지 않고 오류와 작성 내용을 유지한다.
- IndexedDB 대기열은 owner_id가 현재 계정과 일치할 때만 전송한다. 답장 ID와 client_id를 보존하고 동시 flush를 직렬화한다. 소유자를 증명할 수 없는 기존 레코드는 삭제·재전송하지 않는다.
- 전송 응답이 뒤늦게 도착해도 다른 대화방 화면에 삽입하지 않는다. 들어온 메시지의 읽음 처리는 화면이 보일 때만 요청한다.
- 한글/일본어 IME 조합 확정 Enter가 메시지를 전송하지 않도록 한다.
- 현재 브라우저 로그아웃은 기존 기기 해제 API를 사용한다. 토큰과 기기 ID의 저장 위치를 함께 관리한다. 기기 ID를 알 수 없는 이전 세션에서는 서버 전체 로그아웃을 임의 실행하지 않고 로컬 로그아웃과 확인 필요 안내를 한다.
- 모바일 대화방에서는 하단 탭을 숨겨 입력란 가림을 제거하고, 긴 제목과 헤더 도구를 반응형으로 배치했다.

## 실제 검증

등록·친구 추가·대화방 생성은 실제 로컬 API로 수행했다. 이후 분리된 실제 Edge 브라우저 컨텍스트 두 개에서 웹 로그인·전송·수신·로그아웃을 실행했다. 서버 응답 모의는 사용하지 않았다.

## 상태 지표 오류 정정

기존 system/health는 published_at IS NULL을 세어 outbox pending 490을 반환했다. 실제 릴레이는 outbox_deliveries에 인스턴스별 처리 기록을 남기므로, 490을 실제 미처리 이벤트로 판단할 수 없었다. 사용자에게 이 오해를 정정했다.

현재 인스턴스의 처리 기록과 대조하도록 수정했다. 조회 실패를 0으로 숨기지 않고 degraded/unhealthy 및 pending=null로 표시한다. 실제 임시 DB 테스트로 처리 전 1 → 처리 후 0, 다른 인스턴스에서는 1, 테이블 조회 실패는 비정상을 확인했다. 수정된 로컬 서버에서 database healthy, outbox pending=0/healthy를 확인했다. pending=0은 수신자가 실제 읽었다는 보증이 아니다.

## 운영 및 외부 연동 확인 범위

- 운영 /api/v1/version: 2188e8f4b97a6aeacbf03c5e6ffd2124f8cb1cab. 이번 미커밋 개선은 운영 반영하지 않았다.
- 운영 /healthz, /readyz: HTTP 200. Worker 코드가 고정 ok를 반환하므로 DB·외부 연동 정상 증거로 확대하지 않는다.
- 운영 D1 읽기 연결: Wrangler 원격 SELECT 1 AS connectivity 성공, changes=0, rows_written=0, changed_db=false. 운영 쓰기→상대 수신 및 DB 복원은 이번에 실행하지 않았다.
- 운영 /api/v1/system/health: 비인증 조회 401. 이를 전체 정상으로 판정하지 않았다.
- 로컬 Go: FCM/APNs 자격 증명 미설정. 운영 푸시 자격 및 실제 도달은 미검증이다.
- 현재 Worker 설정: USER_HUB/Durable Objects 없음. 서로 다른 isolate의 즉시 소켓 전달은 보장하지 않는다. 로컬 10초 복구 경로는 아직 운영 미반영이다.
- 운영 PostgreSQL 라우팅, 첨부파일 전 구간, 실기기 통화/STUN/TURN, 푸시 도달, 번역 제공자, 결제, DB 백업·복원, 모든 콘솔의 권한별 업무 흐름은 전체 검증되지 않았다. 기존 게이트는 유지한다.
- GitHub 자동 배포는 CLOUDFLARE_API_TOKEN 누락 상태다. 이전 로컬 배포 성공이 CI 인증 연결 완료를 의미하지 않는다.
- E2EE/Letter Sealing의 완전한 프로토콜 구현·상호 운용성을 이번 텍스트 테스트로 인증하지 않는다.

따라서 판정은 **로컬 핵심 메시징 경로 검증 통과, 전체 운영 데이터 파이프라인 검증 미완료**다. 운영 DB 변경·마이그레이션, 새 운영 배포, 커밋·푸시는 이번 작업에서 수행하지 않았다.

## 후속 작업: 미디어 및 실제 공유 경로 연결

사용자의 후속 지시에 따라 파일 저장→대화 연결→상대 조회→다운로드 경로를 추가로 검증하고 다음을 구현했다.

- MessageAttachment 컴포넌트가 현재 계정의 Authorization 헤더로 실제 첨부 바이트를 조회하여 사진·음성·영상 미리보기를 제공한다. 알려진 안전한 미디어 MIME만 미리보기에 사용하고 그 외 파일은 다운로드한다. URL에 토큰을 넣지 않는다.
- 인증 변경·메시지 취소·컴포넌트 종료 시 요청을 취소하고 Blob URL을 폐기한다. 서버 오류를 성공 미리보기로 표시하지 않고 오류·재시도를 제공한다.
- 파일·실제 화면 캡처·음성 녹음은 같은 실제 업로드 경로를 사용한다. 전송 대상 대화와 세션을 캡처하여, 업로드 도중 다른 계정/대화로 전환되어 잘못 전송되는 것을 방지한다. 기존 512 KiB 한도를 유지한다.
- 위치 공유는 실제 Geolocation 권한 및 좌표를 사용한다. 권한 거절 시 고정 서울 좌표를 보내지 않는다. 연락처는 실제 친구 목록에서 선택하며 임의 연락처를 만들지 않는다.
- 화면 캡처는 실제 getDisplayMedia와 캔버스 이미지 업로드로 구현했다. 기존의 텍스트만 전송하는 가짜 캡처 성공 경로를 제거했다. 실제 OS 화면 선택·캡처 QA는 NOT TESTED다.
- 마이크 녹음의 업로드 계정·대상을 고정하고, 로그아웃/종료 시 미전송 녹음을 폐기하고 트랙을 정지한다. 실제 마이크 및 모바일 실기기 QA는 NOT TESTED다.
- 임의 문자열/서명을 키 번들로 제출하던 로그인 초기화·키 갱신 경로를 제거했다. 검증된 E2EE 프로토콜을 구현한 것으로 가장하지 않고 준비 상태로 표시한다. 기존 게이트 및 서버 키 API 계약은 변경하지 않았다.
- 보안 알림의 가짜 IP·도시·Windows 로그인 폴백을 제거했다. 서버에 없는 값은 미확인으로 표시한다. 다크 모드 대화 제목·발신자·시각·도구의 대비도 보정했다.

### 추가 검증 결과

실제 API로 검수 계정 3개를 생성하고 2개의 분리된 Edge 브라우저에서 전송/수신을 실행했다. 바이너리 2,053바이트, 승인 로고 PNG 9,032바이트, 유효한 WAV 샘플 파일 16,044바이트를 실제 파일 선택 입력으로 업로드했다. 세 파일 모두 상대 다운로드 바이트의 SHA-256이 원본과 일치하고 대화방 외 세 번째 계정은 HTTP 404로 차단되었다. PNG의 실제 디코드와 WAV의 실제 브라우저 재생 메타데이터를 확인했다. WAV 검수 샘플은 마이크 녹음 성공의 증거가 아니다.

새로고침 후 파일 조회, 실제 친구 선택 후 연락처 수신, 위치 권한 거절 시 메시지 POST 없음, light/dark × 390/1440의 가로 넘침 없음이 통과했다. 기존 파일 바이트의 서버 재시작 후 복원·삭제 및 업로드 테스트, 웹 빌드가 통과했다.

로컬 증거: [미디어 결과 JSON](../.vscode/media-live-qa-results.json), [미디어 검수 스크립트](../.vscode/media-live-qa.cjs), [390px 다크](../.vscode/media-live-dark-390.png), [1440px 라이트](../.vscode/media-live-light-1440.png).

Worker /readyz는 실제 D1 SELECT 1 결과를 확인하고 DB 누락/조회 실패 시 503을 반환하도록 수정했다. /healthz는 생존 확인으로 분리했다. 두 경로는 probe만으로 demo boot·DDL·seed를 실행하지 않는다. 새 검증 2개를 포함한 Node 49개 테스트가 통과했다. 이 상태 확인 변경은 아직 운영에 배포하지 않았다. DB 읽기 준비 상태가 외부 푸시·통화 등의 준비 상태를 의미하지 않는다.

기준 e9cbad4 이후 현재 작업 자료를 포함한 고유 변경 경로는 48개로 확인했다. 추가 파일을 무제한으로 늘리지 않는다. 기존 작업 및 증거 파일은 보존했다.

### 실제 운영 연결에 남은 선행 정보

저장소의 배포 문서는 실제 Go 서버/TLS·PostgreSQL·푸시 자격 증명 등의 인프라를 별도로 준비하도록 명시하고 있다. 현재 작업 폴더에는 .env.example만 있고 운영 API 주소나 PostgreSQL 연결 설정은 확인되지 않았다. Cloudflare/D1 접근만으로 해당 연결을 추정하거나 새 유료 서비스를 임의로 생성하지 않았다. 사용자에게 비밀값 대신 기존 운영 서버 주소·설정 파일 또는 관리 콘솔 위치를 요청했다. 그 정보 없이 운영 라우팅·푸시를 연결 완료로 판정하지 않는다. 운영 DB를 변경하거나 이번 소스를 커밋/푸시/배포하지 않았다.
