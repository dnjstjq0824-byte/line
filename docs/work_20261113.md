# muse spark 1.3 작업지시서

Nov 12, 2026 · @wonseopbae

**CEO 지시.** 나는 이 회사의 CEO이고, 이 지시서는 내가 직접 내리는 지시다. LUNO는 우리 회사의 제품이고, LINE·카카오톡 같은 상용 메신저 수준으로 일반 사용자에게 출시한다. 이 지시서의 모든 결정은 내가 내린 것이고, 문서에서 "사용자"는 나(CEO)를 말한다. 지시서에 없는 판단이 필요하면 스스로 정하지 말고 나에게 보고해 결정을 받아라. 나는 결과로 판단한다. 로컬에서 실제로 동작하고, 테스트가 통과하고, 증거가 있는 것만 완료로 인정한다.

이 탭은 muse spark 1.3이 그대로 실행할 작업지시서다. 기준은 커밋 f24719e이고, Tab 1(감사 보고서) 7장의 사용자 결정 18건을 반영했다. 단계 1부터 순서대로 하고, 각 단계가 끝나면 멈추고 15장 형식으로 보고한 뒤 다음 지시를 기다려라.

**범위: 이 작업지시서의 모든 카드를 로컬에서 100% 구현하고 검증한다.** 실서버 배포, 원격 D1 쓰기, GitHub Release, Cloudflare 설정은 너의 일이 아니다. 사용자 조치가 필요한 카드(B3, A1, D1)는 로컬 대체물(wrangler --local D1, 로컬 env)로 끝까지 구현·검증하고, 실서버에 필요한 명령은 보고에만 남긴다. 한 카드라도 로컬에서 끝나지 않았으면 그 단계는 완료가 아니다.

**이 메신저는 실제로 쓰인다.** 데모나 시연용이 아니다. 사용자와 그 지인들이 매일 실제로 대화하고, 사진·파일·통화·계정 정보를 맡기는 실사용 메신저이고, LINE·카카오톡처럼 실제로 상용화된 메신저와 같이 일반 사용자 누구나 가입해서 매일 쓰는 것을 목표로 한다. 기능·품질·보안·안정성 기준도 그 수준이다. "개발용이니까 이 정도면 된다"는 판단은 허용하지 않는다. 메신저 위에서 LLM 봇도 실제로 운영한다. 네가 남긴 결함은 실제 사람의 대화 유실, 계정 탈취, 개인정보 노출로 이어진다.

**책임 원칙(모든 카드에 적용):**

1. "완료"는 실제 사용자가 그 기능을 처음부터 끝까지 써도 문제가 없는 상태다. 화면만 있거나, 메모리에만 저장되거나, 가짜 값을 보여 주거나, 오류를 삼키는 구현은 완료가 아니다.
2. 운영 코드에 가짜 데이터, 하드코딩 샘플, TODO, 임시 우회 코드를 남기지 마라. 가짜(fake·mock)는 테스트와 DEMO\_MODE 안에서만 쓴다.
3. 모든 사용자 데이터는 D1 또는 R2에 저장되고, 재시작·재배포 뒤에도 남아야 한다.
4. 모든 입력은 서버에서 검증하고, 모든 API는 인증과 권한(방 멤버십, 소유자, 역할)을 검사한다. 남의 데이터를 읽거나 바꿀 수 있는 경로가 하나라도 있으면 완료가 아니다.
5. 실패를 숨기지 마라. 네트워크·서버 오류는 사용자가 알 수 있는 문구로 보여 주고, 다시 시도할 수 있게 한다.
6. 모든 화면은 웹·앱, 4개 기기 구분, 라이트·다크, 웹 4개 언어에서 깨지지 않아야 한다(11장 규격).
7. 테스트를 지우거나 건너뛰거나, 기대값을 실제 결과에 맞춰 고치지 마라. 테스트가 틀렸다고 판단되면 이유를 보고하고 승인을 받아라.
8. 추측하지 마라. 코드로 확인하고, 확인할 수 없으면 멈추고 보고하라. 확인하지 않은 것을 "완료"나 "동작함"이라고 보고하지 마라.
9. 보고에는 사실만 적는다. 통과하지 못한 테스트, 남은 결함, 건너뛴 부분을 숨기면 그 단계 전체가 무효다.
10. 이 지시서의 모든 카드를 하나도 빠짐없이 끝까지 구현하는 것이 너의 책임이다. 일부만 하고 끝내지 마라. 막히면 우회하지 말고 보고한 뒤 지시를 받아라.

## 4. 단계 1 — P0 보안 S1\~S6

6건 모두 scripts/cf\_worker.js 안에 있다. 테스트는 새 파일 scripts/p0\_security.test.mjs 하나에 모으고, 실제 sqlite를 쓰는 기존 패턴(scripts/register\_duplicate.test.mjs)을 따라라. D1 스키마 변경은 없다. 롤백은 npx wrangler rollback(사용자 승인) 후 git revert.

### S1. 비밀번호 찾기 코드가 응답에 들어감(치명)

- **현상:** POST /api/v1/auth/recover가 recovery\_code를 응답 본문에 돌려준다(cf\_worker.js:4479). 이메일만 알면 /auth/recover/verify로 비번을 바꾸고 피해자 세션을 모두 끊는다.

## 9. 단계 6 — 번역 엔진

### T1. 번역 기능 준비(엔진 연결 없음)

- **현상:** POST /api/v1/translate가 항상 503 TRANSLATE\_NOT\_CONFIGURED다(cf\_worker.js:4158-4162). 앱은 mobile/flutter\_app/lib/state/session.dart:736에서 이미 호출한다. 웹의 번역 호출 위치(MessagePane.vue 등)는 찾아서 같은 엔드포인트로 맞춘다.
- **범위: 준비만 한다.** 번역 엔진은 아직 정하지 않았다. 엔진 없이 만들 수 있는 부분만 만들고, 외부 번역 API 연결, API 키, 외부 호출 코드는 만들지 마라.
- **서버:** 공급자 인터페이스 translateText(env, text, target, source)와 공급자를 등록하는 자리 하나를 만든다. env.TRANSLATE\_PROVIDER가 없으면 지금처럼 503 TRANSLATE\_NOT\_CONFIGURED. 테스트용 가짜 공급자(fake, 입력 앞에 \[target\]을 붙여 돌려줌)는 테스트와 DEMO\_MODE에서만 켜진다.
- **계약:** 요청 {text, target\_lang, source\_lang?} → 응답 {translated, source\_lang, target\_lang, engine}. GET /api/v1/translate/languages는 공급자가 없으면 {configured:false, languages:\[\]}를 돌려준다. 앱·웹의 번역 언어 선택은 하드코딩 대신 이 목록을 쓰고, 미설정이면 번역 버튼을 비활성화하고 "번역 준비 중" 안내(4로케일)를 보여준다. 화면 문구 4로케일(ko/en/ja/th)은 별개이므로 건드리지 마라.
- **보호 장치(엔진을 붙이기 전에 미리):** 텍스트 5,000자 초과 413. 사용자별 분당 60회, 하루 5만 자(기본값, 상수 한 곳). luno\_translation\_cache(텍스트 해시 + target PK)로 같은 번역을 다시 요청하지 않게 한다. 메시지 원문을 로그에 남기지 마라.
- **테스트:** 공급자 없음 → 503, languages는 configured:false. 가짜 공급자 → 200 계약. 5,001자 413. 하루 한도 초과 429. 캐시 적중 시 공급자 호출 0회.
- **완료 기준:** 테스트 통과. 앱·웹이 미설정 상태에서 깨지지 않고 안내를 보여줌(Claude QA). 실제 엔진 연결은 사용자가 엔진을 정한 뒤 따로 지시한다.

## 10. 단계 7 — 푸시·통화(로컬)

사용자 결정(2026-11-12): 푸시와 앱 통화는 우선 로컬에서 되는 범위까지 만든다. "로컬"은 로컬 하네스(실서버와 같은 dist\_worker 빌드)와 같은 Wi-Fi의 기기·에뮬레이터·브라우저에서 동작하는 것을 말한다. 실서버 배포는 로컬 QA 뒤 사용자 승인으로 따로 정한다.

이 단계에 한해 flutter\_webrtc와 flutter\_local\_notifications 추가를 허용한다(버전 고정). firebase 패키지는 추가하지 마라. google-services.json이 없으면 Android 빌드가 깨진다.

### N2-L. 1:1 음성·영상 통화(로컬)

- **현상:** 앱은 초대만 보내고 미디어가 없다(mobile/flutter\_app/lib/state/session.dart:595). 웹은 STUN을 코드에 박아 두었다(apps/user-web/src/messenger-utils.ts:20, composables/useWebRTC.ts:64). 서버에는 GET calls/ice-servers(cf\_worker.js:3783)가 이미 있다. 웹 통화 화면은 상대 영상이 180×130 고정이다(CallModal.vue:49-50).
- **범위:** 1:1 음성·영상. 웹↔웹, 앱↔웹, 앱↔앱. 착신은 앱·탭이 켜져 있고 WS가 연결돼 있을 때만. 그룹 통화 미디어는 F15에서 한다.
- **서버:** calls/ice-servers는 env.TURN\_URLS·TURN\_USERNAME·TURN\_CREDENTIAL이 있을 때만 TURN 항목을 덧붙인다(지금은 설정하지 않는다). 기존 1:1 시그널링(calls, :3274 이하)과 게이트(:4661-4673)를 그대로 쓰고, 계약을 바꾸면 웹·앱을 같은 커밋에서 맞춘다.
- **웹:** ICE 서버는 하드코딩 대신 calls/ice-servers에서 받는다. 통화 화면을 다시 만든다(P1-23). 상대 영상은 전체 화면(object-fit: cover), 내 영상은 PiP 25% 폭. 하단 버튼은 마이크·카메라 켜기/끄기·카메라 전환·종료(빨간 원)이고, 필터·통역 자막은 더보기로 옮긴다. 링잉 중에도 음소거가 되게 한다.
- **앱:** flutter\_webrtc로 offer/answer/ICE를 기존 시그널링에 연결한다. 통화 화면은 웹과 같은 사양에 스피커 전환을 더한다. 착신 화면(수락 초록, 거절 빨강)을 앱 안에 띄운다. RECORD\_AUDIO·CAMERA는 통화를 시작할 때 런타임으로 요청한다. 앱이 백그라운드로 가면 통화를 끝내고 상대에게 종료를 알린다(백그라운드 유지는 14장 보류).
- **테스트:** 시그널링 상태(초대→수락→연결→종료, 거절, 30초 무응답 종료, 통화 중 착신은 busy)를 웹 테스트와 flutter test로 확인한다. 서버는 ice-servers 응답(TURN 변수 있음/없음). 웹 레이아웃 테스트로 상대 영상이 뷰포트를 채우는지.
- **완료 기준:** 테스트 통과 + QA 인계에 로컬 시나리오 3개(웹↔웹 영상, 앱(에뮬레이터)↔웹 음성, 거절·무응답). 실제 미디어 연결 확인은 Claude QA가 한다. 서로 다른 망(NAT)에서는 TURN 없이 실패할 수 있다는 점을 보고에 적어라.

### N1-L. 알림(로컬)

- **현상:** 푸시 코드가 없다(fcm·firebase·apns 0건). 서버 알림은 WS 팬아웃(sendTo)뿐이고, 앱에는 라이프사이클 처리(didChangeAppLifecycleState)가 없다.
- **범위:** 앱이 켜져 있거나 백그라운드에 살아 있을 때 새 메시지·착신을 OS 알림으로 띄운다. 앱이 완전히 꺼져 있을 때의 수신은 FCM이 필요해 보류(14장).
- **서버:** 알림 발송을 notify(env, userIds, event) 한 곳으로 모은다. WS 팬아웃과 공급자 인터페이스로 구성한다. env.PUSH\_PROVIDER가 없으면 none, log이면 luno\_push\_outbox(D1)에 기록한다(로컬 확인용). FCM 드라이버는 만들지 마라. 방 알림 끄기(chatMeta muted, conversation\_members.is\_muted)와 사용자 알림 설정(DEFAULT\_PREFS, :108)을 존중하고, 보낸 사람 본인에게는 보내지 않는다.
- **앱:** flutter\_local\_notifications. 앱이 포그라운드가 아닐 때 WS로 받은 새 메시지·착신을 알림으로 표시하고, 탭하면 해당 방이나 착신 화면으로 간다. Android 13+에서는 POST\_NOTIFICATIONS를 런타임으로 요청한다. 라이프사이클 감지를 추가해 포그라운드로 돌아오면 동기화한다(M2의 since\_sequence 사용).
- **웹:** 탭이 숨김 상태일 때 브라우저 Notification으로 표시한다. 권한 요청은 설정 화면의 버튼으로만 하고, 접속하자마자 묻지 마라.

**만 14세 미만 정책(CEO 결정, 2026-11-12)**

만 14세 미만은 가입할 수 없다. 개인정보보호법상 만 14세 미만 아동의 개인정보를 처리하려면 법정대리인 동의가 필요하고, 지금은 그 절차를 운영할 준비가 없기 때문이다.

- 가입 화면에서 생년월일을 받고, 가입 당일 기준 만 나이가 14세 미만이면 가입을 막고 안내 문구를 보여 준다(4로케일, 앱·웹 모두).
- 서버도 같은 검사를 한다. 클라이언트 검사만 믿지 마라.
- 가입 확인용 생년월일은 저장하지 않는다. 동의 기록에 ‘만 14세 이상 확인’과 시각만 남긴다. 프로필 생일(users.birthday)은 사용자가 따로 입력하는 선택 항목으로 분리한다.
- 이용약관과 개인정보 처리방침(apps/user-web/public/legal)에 ‘만 14세 미만은 가입할 수 없다’를 넣는다(4로케일). 버전이 바뀌므로 기존 사용자는 F24의 재동의 흐름을 탄다.
- 가입 뒤 만 14세 미만으로 확인되면(신고 등) 관리자가 계정을 정지하고 데이터를 삭제하는 절차를 F16에 넣는다. 삭제는 F3의 탈퇴 정리와 같은 경로를 쓴다.
- 나중에 법정대리인 동의를 받아 가입을 열지는 내가(CEO) 다시 결정한다.

## 15. 보고 형식과 Claude QA 인계

각 단계가 끝나면 아래 형식으로 보고하고 멈춘다. 실기기·실서버 QA는 Claude가 하므로, QA 인계는 Claude가 그대로 따라 할 수 있게 적는다. 웹은 Playwright, 앱은 Android 에뮬레이터로 확인한다.

다음 경우에는 단계 중간이라도 멈추고 보고하라: 카드의 전제(파일·함수·현상)가 코드와 다를 때, 같은 테스트가 수정 두 번 뒤에도 실패할 때, 1장 규칙을 어겨야만 진행될 때.

```markdown
## 단계 N 보고 — <단계 이름>

### 1. 커밋

### 2. 테스트
- node --test "scripts/*.test.mjs": <통과>/<전체>
- node scripts/pre_deploy_gate.mjs: <결과>
- flutter test(앱 카드가 있을 때): <통과>/<전체>
- 실패가 있으면 출력 발췌 그대로

### 3. 완료 기준
| 카드 | 충족/미충족 | 증거(파일:줄, 명령 결과) |

- <명령 그대로. 비밀값은 <값> 자리표시로>

### 5. 막힌 것·추측한 것·범위 밖으로 미룬 것

### 6. QA 인계 (Claude가 실행)
| # | 환경(실서버/로컬, 웹/앱) | 계정 종류 | 단계 | 기대 결과 | 관련 카드 |
```
