# 그룹 통화 QA 시나리오 (F15)

로컬에서 3명이 그룹 음성·영상 통화를 검증한다. 서버 시그널링은
`calls/group/join|signal|leave` + WS `call.group.*` 팬아웃이며, 미디어는
참가자 간 WebRTC 메시(최대 8석, 9번째는 409)다. 제안을 보내는 쪽은
새로 들어온 참가자(joiner-offers)로 고정돼 있어 offer 충돌이 없다.

## 준비

```sh
npx wrangler dev --port 8791 --config wrangler.jsonc
```

- 계정 3개를 만든다 (웹 가입 화면 또는 앱).
- A가 B·C를 멤버로 그룹방을 만든다 (대화방 → 그룹 만들기).
- 3명 모두 그룹방에 들어간다. 공식계정 방에서는 그룹통화가 막힌다.

## 시나리오 1 — 웹↔웹↔웹 영상 통화

1. A가 그룹방 헤더의 영상통화 버튼을 누른다.
   - 타일 화면이 뜨고, 본인 타일 + "다른 참가자를 기다리는 중..." 표시.
2. B가 같은 방에서 영상통화 버튼을 누른다.
   - B 화면: A·B 2타일. A 화면: B 타일 추가 (WS `user_joined`).
   - 양쪽 모두 상대 영상이 보이면 메시 연결 성공.
3. C가 음성통화 버튼으로 참가한다 (음성+영상 혼합).
   - 3명 화면 모두 3타일. C 타일은 아바타(음성), A·B는 영상.
4. A가 마이크를 끈다 → A 타일에 음소거 표시.
5. B가 통화를 종료한다 → A·C 화면에서 B 타일이 사라진다 (`user_left`).
6. B가 다시 참가한다 → 타일이 돌아오고 영상이 다시 보인다 (재참가).

## 시나리오 2 — 앱(에뮬레이터)↔웹 음성 통화

1. 에뮬레이터 앱에서 C로 로그인 → 그룹방 → 음성통화 버튼.
2. 웹 A·B가 참가한다. 3타일이 양쪽에 모두 보인다.
3. 앱을 백그라운드로 보낸다 → 통화가 끝나고 A·B 화면에서 C 타일이
   사라진다 (백그라운드 유지 금지, N2-L과 동일 규칙).
4. 앱을 다시 열어 참가한다 → 타일이 돌아온다.

## 시나리오 3 — 정원·busy·고스트

1. 8명이 참가한 방에 9번째가 참가 → "통화 인원이 가득 찼습니다
   (최대 8명)" 안내, 타일 화면이 뜨지 않는다 (서버 409).
2. 그룹 통화 중 1:1 전화가 걸려오면 자동 거절 + "다른 통화 중입니다".
   역으로 1:1 통화 중 그룹 참가 시도도 같은 안내로 막힌다.
3. 참가 중 탭을 닫는다(WS 연결 끊김) → 서버가 해당 좌석을 비우고 나머지에
   `user_left`를 뿌린다. 좌석이 고스트로 남지 않는다.

## 자동 테스트

```sh
node --test scripts/f15_group_call.test.mjs   # 서버 3종 + 트립와이어 3종
flutter test test/group_call_test.dart         # 앱 메시 10종 (가짜 미디어)
```

## 주의

- 서로 다른 망(NAT)에서는 TURN 없이 미디어가 실패할 수 있다
  (N2-L과 동일, `calls/ice-servers`에 TURN 설정 시 해소).
- 실제 미디어 연결 확인은 QA 클릭으로 한다. 자동 테스트는 시그널링·
  상태기계·배선을 고정한다.
