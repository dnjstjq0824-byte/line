## C. 실제 코드 수정과 기능 상태

1. **파트너 권한 경계**: 일반 사용자가 다른 공식 계정의 메뉴/봇/상담 API를 읽거나 변경하던 경로를 조직 소유자/관리자로 제한했다. 조직 목록도 소유자 범위로 제한했다. 기존 성공 기대 테스트를 올바른 거부 기대로 수정했다.
2. **Go 암호화 메시지 검색**: 암호문에 SQL LIKE를 적용하던 오류를 복호화 후 검색하도록 수정했다. 오래된 메시지, 리터럴 `%`, 삭제 메시지, 비참여자 거부를 실제 격리 DB로 검사했다. 검색은 O(n)이며 대규모 성능 검증/인덱스 설계가 남는다. Cloudflare 단독 런타임에는 Go 서버가 배포되지 않는다.
3. **준비 상태**: SELECT 1만 성공하는 빈 DB를 정상으로 보던 오류를 수정했다. 필수 8개 테이블을 확인하며 검사 자체는 테이블/데이터를 생성하지 않는다. 운영 테이블 존재는 읽기 전용 확인했으나 전체 DB 관계/무결성 감사 완료는 아니다.
4. **가짜 공급자 성공 제거**: 실제 공급자가 없는 푸시 테스트, STT, Webhook 전송 테스트, 결제, 정산 요청은 503 및 구체 오류를 반환한다. 없는 암호화 키는 404다. 이 기능들이 구현 완료됐다는 뜻이 아니다.
5. **실시간 통신**: 실제 로컬 workerd + D1 + Durable Objects에서 두 WebSocket의 단일 수신, client_id 재시도 중복 방지, 단절 후 since_sequence 복구를 검사했다. 동기화는 D1에서 sequence 오름차순으로 최대 500개씩 읽고 다음 페이지 존재 여부와 반환 마지막 커서를 제공한다. 이전 메모리 의존 복구 경로를 수정했다.
6. **배포 식별**: 버전 응답에 소스 dirty 여부와 Worker SHA-256을 추가했다. HEAD만으로 미커밋 배포를 동일 소스라고 표시하지 않는다.

503개의 지속 메시지 복구 검사는 500개 첫 페이지 + 나머지 페이지를 합쳐 고유 ID 503개 및 sequence 1..503 연속성을 확인했다. **이 조건에서만** 누락·중복이 없었다. 서버 재시작/다중 isolate/경합/실제 이동통신 장애 전체에 대한 메시지 0유실 주장은 하지 않는다.

[QA 레지스트리](./qa-registry.json): 후보 5,998건, NOT_RUN 5,994, BLOCKED 4, PASS 0. 실제 실행 기록은 위 별도 증거 파일에 보관한다. 후보 수를 실행 수 또는 품질 완성률로 사용하지 않는다. 전체 후보와 실제 검사 간 연결·정책 검토는 추가 작업이다.

로컬 신규 DB에서 초기 users 테이블 부재로 등록이 실패한 사실을 확인했다. 초기 SQL을 **격리된 로컬 D1에만** 적용해 검사했다. 운영 DB 스키마 변경은 실행하지 않았다. 런타임 스키마 부트스트랩을 명시적 배포 마이그레이션으로 정리하는 작업이 남는다.

## F. 배포 및 다음 개발 순서

운영: https://line-messenger.dnjstjqppk.workers.dev/ . 별도 유료 계약·시크릿 교체·파괴적 DB 변경·스토어 제출을 실행하지 않았다. SQLite Durable Objects는 Free에서도 지원되며 유료 플랜 필수라는 과거 주장은 정정한다: [Cloudflare 공식 제한](https://developers.cloudflare.com/durable-objects/platform/limits/).

롤백 시 직전 정상 버전을 재배포하되 USER_HUB namespace와 migration 이력을 보존한다. namespace 삭제 마이그레이션으로 롤백하지 않는다. 소켓 namespace 유지가 대화 메타데이터의 지속성을 보증하지는 않는다.

다음 순서:
1. 기존 LN5 계약과 새 요구사항을 대조해 대화/멤버십 및 CRM 지속 저장 계약을 확정하고, 비파괴 마이그레이션·롤백을 작성한다.
2. 신규 사용자 대화를 Worker 재시작/다른 isolate에서도 복구하고, 소유권·동시 전송·중복·페이지 복구 회귀를 확대한다.
3. 실제 신규 파트너의 메뉴 편집→저장→발행→사용자 노출→봇 응답을 끝까지 연결한다.
4. 인증된 사용자와 각 역할 콘솔 전체 화면을 감사하고 디자인 토큰/컴포넌트/반응형/접근성을 통합한다.
5. 실제 공급자와 실기기를 확보한 항목에 한해 푸시·통화·Android/iOS 검증을 수행한다. 필요한 자격증명/계약/스토어 권한은 해당 항목에 한해 구분한다.
6. 실행 QA와 후보 레지스트리를 연결하고 P0/P1 해결 후 스테이징·운영 검사 및 최종 인계를 수행한다.
